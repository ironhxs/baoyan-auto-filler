# 保填 Agent 2.1：统一页面蓝图与跨页智能规划设计

## 1. 目标与范围

本次增强的目标是让“识别并预览”和“连续填写”共享同一套页面蓝图、动作协议、本地校验和执行器，避免预览结果、自动填写结果和写后回读结果出现三套逻辑。单页预览生成页面计划；后台连续填写先收集全部可到达页面，再生成覆盖整批页面的全局计划。Agent 需要理解报名页面真实可见的题干、注释、格式限制、表格列结构、重复行和当前值，并结合已保存资料将同一份事实转换为不同学校的实际页面结构。

本次范围包括：

- 将单页预览接入 Agent observe → retrieve → plan → validate 流程，但预览阶段不执行网页写入。
- 后台连续填写先只读收集当前报名任务的全部可到达页面，再一次性生成跨页全局计划；缓存按页面结构、资料、模型、协议和 Fast 设置失效。
- 增加学校、院系、项目三层页面身份，并在当前网站、连续填写和统一审核中统一显示。
- 删除“保守 / 标准 / 尽量填充”三种模式，改为 Agent 安全校验后的单一执行策略；保留逐条勾选、取消、定位和人工处理。
- 修复重复表格标注造成的视觉布局问题，标注不得增加控件或表格的布局尺寸。
- 强化学术成果语义分流，禁止将竞赛或科研训练机械映射到论文刊物、作者排名、奖励地点等不相符列。

不在范围内：

- Word/PDF 个人资料智能导入。
- 自动提交、保存、确认报名、志愿/导师选择、承诺书、验证码、支付、删除等高风险操作。
- 本地模型或第三方自建服务器。

## 2. 用户流程

### 2.1 识别并预览

用户点击“识别并预览”后，扩展执行：

1. content script 采集当前页面蓝图。
2. background 读取当前任务已有页面上下文和本地资料记录。
3. Agent API 返回严格 JSON 页面计划。
4. 本地策略校验计划，过滤高风险动作、保护非空人工值、检查证据字段和重复行一致性。
5. 扩展缓存计划和页面快照，展示字段匹配、来源、置信状态、人工确认项，并在网页上标色。
6. 不执行 fill、select、upload、add_rows。

### 2.2 一键填写

用户点击“一键自动填写”后：

- 优先复用当前页面已缓存且指纹一致的 Agent 计划。
- 若页面结构、资料或 API 配置已变化，重新规划当前页。
- 执行白名单动作，执行后逐项回读。
- 绿色表示回读一致，橙色表示需要确认，红色表示回读不一致；失败或证据不足时暂停，不自动进入高风险操作。

### 2.3 连续填写：先收集，再综合规划，再执行

连续填写改为明确的三阶段状态机，避免“填完一页才发现后面页面需要同一资料”的局部贪心行为：

#### 阶段一：页面收集（只读）

- 从当前入口开始，按页面明确的“下一步/保存并下一步/继续”语义遍历可到达页面。
- 只允许读取页面、读取题干和字段、读取现有值、读取可见材料入口；不写字段、不选择业务选项、不保存、不提交。
- 每页保存完整 `AgentPageSnapshot`，包括学校、院系、项目、题干、注释、格式限制、表头、行列结构、当前值和材料入口。
- 如果遇到验证码、承诺书、志愿/导师选择、最终确认或无法确认的导航控件，立即停止收集并将该页面标记为人工处理，不点击该控件。
- 页面收集可以在后台继续，用户关闭弹窗或切换到其他标签页不会丢失已收集快照。

#### 阶段二：全局综合规划

- 将本批次已经收集的全部页面蓝图、学校/院系/项目身份和资料记录一次发送给 Agent。跨页规划的硬要求是：Agent 必须逐页看到每一个报名页面的完整提示和结构，不能只接收“基本信息/奖励情况”等摘要标签。
- 批次 prompt 按页面分段，每段至少包含该页的完整题干、相邻说明、日期示例、禁止字符、长度限制、字段标签、placeholder、可选项、表头、列顺序、重复行结构、当前值、人工保护状态和材料题目；页面之间使用稳定的 `pageKey` 分隔。
- Agent 返回带 `pageKey` 的批次计划，每个动作必须绑定具体页面、目标字段、来源记录和证据字段。
- Agent 必须全局解决资料分配和语义转换：例如同一份科研训练分别转换为科研训练表、项目经历表或学术成果长文本；奖励资料不能被竞赛记录占用；同一页面的多列表格必须整行一致。
- 本地策略逐页验证计划，发现页面不存在、来源证据缺失、目标列语义不相容、覆盖人工值或包含高风险动作时，整项进入人工确认，不执行半行写入。
- 全局计划和每页子计划分别缓存；任何页面结构、资料、模型、协议或 Fast 设置变化都会使对应计划失效。

#### 阶段三：逐页执行与回读

- 按收集顺序回到每一页，复用全局计划中的对应子计划。
- 只执行已经通过本地校验的白名单动作，执行后逐字段或整行回读。
- 页面切换、用户手动修改或回读不一致时，暂停当前页并保留全局计划、执行历史和已收集快照；不重新把旧页面计划套到新页面。
- 到达最终审核页后自动停止，统一审核中心展示整批学校/院系/项目的结果。

当任务有多个学校或同一学校多个项目时，页面身份使用：

```text
学校 · 院系 · 项目
```

缺失时按层级降级为：

```text
学校 · 院系未识别
系统标题 · 当前网站
```

## 3. 页面蓝图数据模型

`AgentPageSnapshot` 增加或明确以下信息：

- `institutionName`：从页面可见标题、Logo 文本、学校名称、面包屑和已保存学习信息中推断。
- `departmentName`：从院系、学院、系所、招生单位等可见文案推断。
- `projectName`：从项目名称、报名批次、夏令营/预推免项目标题推断。
- `questionContext`：完整题干及其相邻说明，包含日期示例、禁止字符、长度和填报要求。
- `groupLabel`、`columns`、`rowIndex`、`columnId`：用于重复表格整行语义映射。
- `currentValue` 和 `protected`：区分已有值、人工修改值和必须人工处理的控件。
- `materials`：当前上传题目、网页已有材料、候选文件和预览证据。

发送给模型前进行安全清洗：

- 移除 Cookie、Authorization、CSRF、密码、验证码、支付字段及原始响应。
- 页面 HTML 只保留语义容器、题干、表头、标签和控件属性，不发送脚本、样式、iframe、Canvas 或事件处理器。
- 当前值可以参与核对，但不写入 Agent 状态摘要中的原始响应。

后台连续填写新增 `ApplicationBatchBlueprint`：

- `taskId`、`batchId`、学校/院系/项目身份；
- `pageOrder` 和全部安全清洗后的 `AgentPageSnapshot`；
- 收集是否完整、停止原因和人工页面列表；
- 资料指纹、页面集合指纹和 API 配置指纹。

全局规划新增 `AgentBatchPlan`：

- 批次级指纹和总体说明；
- 按 `pageKey` 分组的页面子计划；
- 跨页资料分配记录；
- 批次级人工确认项；
- 每个页面仍使用现有白名单动作和证据绑定规则，不能绕过页面级本地校验。

## 4. Agent 计划与提示词

单页“识别并预览”调用 `requestAgentPagePlan`；后台连续填写在收集完成后调用 `requestAgentBatchPlan`。两者使用同一页面快照结构、动作 JSON Schema、证据字段和本地校验器。批次计划只是多个页面子计划及跨页分配信息的外层容器，不能建立第二套动作协议。

页面和批次提示词必须明确包含：

- 学校/院系/项目身份；
- 页面标题和步骤；
- 每个字段的完整题干、注释、格式、禁止字符、最大长度、选项；
- 字段所在局部 HTML 语义容器；
- 重复组表头、列顺序、行号和整行边界；
- 当前值和人工保护状态；
- 单页预览发送当前页完整蓝图，并可附带已缓存任务摘要；批次规划发送本次已收集的全部页面完整蓝图；
- 批次 prompt 必须保留逐页原始语义，不得把不同页面的题干、列名或注释合并成一个模糊摘要；
- 资料记录的分类、条目序号、字段值和证据来源；
- 不能编造事实，证据不足必须 `needsReview=true`；
- 禁止提交、保存、确认报名、验证码、支付、删除等动作。

计划返回后，本地必须校验：

- targetId 属于当前快照；
- sourceRecordId 和 evidenceFields 真实存在；
- 重复行同一行绑定同一资料记录；
- 学术成果语义类别与目标列结构相容；
- 非空受保护值不得被覆盖；
- 不允许出现高风险动作或未知动作。

批次计划还必须校验：

- 每个 `pageKey` 都来自本次页面集合；
- 每页子计划的页面指纹与收集时一致；
- 跨页分配引用的资料记录真实存在；
- 不允许用“已经在其他页面使用”为理由删去页面本身明确要求的重复事实；跨页规划解决的是表达和归类，而不是擅自省略必填内容；
- 如果页面集合不完整，批次计划必须明确标记降级范围，不能假装已经看过未收集页面。
- 如果一次请求超出模型上下文限制，只能按页面边界分块；每个页面的完整提示必须进入某一个分块，分块计划必须携带页面指纹并由本地确定性合并，禁止通过截断或随机抽样丢弃页面规则。

## 5. 学术成果语义规则

模型和本地校验共同使用目标字段语义，而不是只按“成果/奖励”等关键词匹配：

| 页面结构 | 允许来源 | 禁止误用 |
|---|---|---|
| 论文名称、类型、发表状态、发表年月、分区、本人排名 | 已发表论文 | 科研训练、竞赛、荣誉奖励 |
| 专利权人、专利名称、授权/受理时间 | 已取得专利 | 竞赛或奖项名称 |
| 项目名称、项目描述、项目时间段、本人角色 | 科研训练、明确项目经历 | 荣誉奖励名称 |
| 获奖人、获奖项目、竞赛名称、获奖等级、获奖时间 | 学科竞赛 | 奖学金或三好学生 |
| 奖项名称、级别、等级、获奖时间、主办单位、描述、本人排名 | 荣誉奖励 | 竞赛项目名冒充奖项地点 |
| 混合长文本“学术成果” | 科研训练、论文、专利、竞赛，按题干组织 | 只机械拼接原始字段 |
| “何时何地何原因受过何种奖励” | 荣誉奖励 | 科研训练、论文、竞赛项目 |

如果页面是整段文本框，Agent 需要按题干生成自然、简洁、事实可追溯的段落；如果页面是多列表格，Agent 必须先理解列职责，再输出整行计划。缺少明确排名、作者身份、地点或发表状态时，保留人工确认，不得猜测。

## 6. 标注与布局修复

扩展的网页标注使用不参与布局的 `box-shadow: inset` 或 `outline`，不得给输入控件设置 margin、padding、height 或 display 属性。对于嵌套重复表格：

- 识别外层题干单元格及其右侧表格；
- 记录原始 `style` 和计算出的 `vertical-align`；
- 仅在必要时设置 `vertical-align: top`；
- 通过 data 属性标记并在清除标注时恢复原值；
- 真实页面验证识别前后题干 `getBoundingClientRect()`，确保题干不会随内层表格向下漂移。

## 7. UI 变化

- 移除 fill-policy 三按钮及相关状态持久化。
- 预览结果继续支持单条 checkbox、定位和人工跳转。
- Agent 计划卡片显示“本页新计划 / 使用缓存计划 / 需要人工确认 / 回读一致 / 失败”等状态。
- 当前网站与统一审核使用同一 `displayName`，至少包含学校和院系。
- 学术成果字段显示计划来源类别和目标列语义，便于发现“竞赛填入论文列”等错误。

## 8. 缓存与失效

单页计划和批次计划缓存指纹至少包含：

- 单页预览使用当前页面蓝图；批次计划使用全部已收集页面及其顺序；
- 参与规划的资料记录；
- API Base URL、模型、协议和 Fast 设置；
- Agent 协议版本。

以下情况必须失效：页面结构变化、资料变化、模型或协议变化、Fast 设置变化、用户手动修改页面后导致回读指纹变化。缓存失效时重新规划，不复用旧计划覆盖新页面。

## 9. 测试与验收

自动化测试覆盖：

- 预览和连续填写共享页面蓝图、动作协议、本地校验和执行器；
- 连续填写在任何写入前先完成多页只读收集，并生成一个批次计划；
- 批次计划按 `pageKey` 正确拆分为页面子计划，页面指纹不一致时拒绝执行；
- 批次请求确实包含每一个已收集页面的完整题干、注释、格式规则和列结构，且测试能证明没有只发送页面摘要；
- 全局上下文加入 prompt 且高风险字段被过滤；
- 学术成果语义分流和跨列转换；
- 单一填写模式 UI 不再出现三种策略；
- 学校/院系/项目显示名在 popup、连续记录和统一审核一致；
- 标注清除后布局样式恢复；
- 缓存指纹在页面、资料、模型、协议或 Fast 变化时失效。

真实浏览器验收只允许扫描、预览、临时填写和回读：

- 东南大学、复旦大学、中山大学等真实页面至少各验证一个普通字段页、一个重复表格页和一个学术成果/奖励页；
- 清空或临时备份字段后从头验证时，禁止点击下一步、保存、确认报名或最终提交；
- 记录每页 Agent 规划次数、缓存命中、计划动作数、回读一致数、人工确认数和失败数。

## 10. 版本与交付

本次涉及预览链路统一、全局上下文和 UI 行为调整，版本升级为 `2.1.0`。完成后需要：

- 更新 Chrome/Edge 和 Firefox 构建；
- 更新 README 和 release notes；
- 运行 TypeScript 编译、现有自动化测试和正式构建；
- Git 提交并核对远程同步状态；
- 不把真实个人资料、API Key、登录状态或浏览器缓存放入仓库、构建产物或 release。
