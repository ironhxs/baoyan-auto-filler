# 保填多网站任务与 AI 最终统一审核设计

## 目标

在不改变“绝不自动最终提交”的安全边界下，让用户可以同时在多个学校报名网站运行自动填写，并在填写结束后手动发起一次统一审核。扩展弹窗优先展示当前网站，独立审核中心汇总本批次所有已完成或暂停的网站、页面字段和上传材料。

目标版本为 `v1.3.3`。

## 已确认的产品原则

1. 当前网站优先：打开扩展弹窗时，当前标签页对应学校的进度、问题和材料必须占主要区域。
2. 全局审核独立：多学校汇总和 AI 最终审核在完整扩展页面中完成，不把复杂报告塞进窄弹窗。
3. 任务持久化：关闭标签页后，学校任务、页面历史、材料记录和审核结果仍保留，直到用户主动归档或删除。
4. 手动触发外发：只有用户点击统一审核并确认发送清单后，相关数据才发送到用户配置的模型服务商。
5. 只读审核：最终审核不修改字段、不重新上传材料、不点击下一步，也不执行任何提交、确认、支付、验证码、承诺书、志愿或导师选择。
6. 通用实现：所有任务识别、页面采集和材料发现基于通用语义与浏览器能力，不引入只对东南大学 DOM、路由或文案生效的核心逻辑。

## 用户流程

### 当前网站

1. 用户在某学校页面打开扩展。
2. 弹窗顶部显示学校或网站名称、当前步骤和任务状态。
3. 主区域显示当前网站的已核对字段、冲突、缺项、材料和逐页历史。
4. 底部仅显示本批次的精简汇总，例如“4 所学校，2 所待审核”，并提供“打开统一审核”按钮。
5. 当前标签页尚未绑定任务时，用户开始连续填写后创建新任务；恢复已有任务时由扩展基于保存的任务和当前网站提示继续，而不是静默合并不确定记录。

### 多网站并行填写

1. 每个开始连续填写的标签页绑定一个持久化申请任务。
2. 本地字段扫描和匹配可以并行执行。
3. AI 请求进入全局队列，最多同时执行 2 个，避免中转线路因瞬时并发出现 `502`。
4. 某个任务暂停、失败或等待材料确认时，不影响其他任务继续运行。
5. 标签页关闭后仅解除标签页绑定，不删除申请任务。

### 最终统一审核

1. 用户打开审核中心。
2. 默认勾选本批次所有已完成或暂停的任务；用户可以取消勾选个别学校。
3. 当前网站排在第一位并高亮。
4. 发送前展示学校数、页面数、字段数、材料数、材料来源和预计抽取页数。
5. 用户再次确认后才调用 API。
6. 报告按学校和页面分组，显示严重错误、疑似问题、缺失材料、跨页面矛盾、未完成检查及已确认项。

## 数据模型

### ApplicationTask

申请任务保存在 `chrome.storage.local`，不再只保存在 `chrome.storage.session`。

建议字段：

- `id`：创建任务时生成的稳定 UUID。
- `batchId`：本次申请批次标识，用于统一审核默认选择。
- `siteOrigin`：网站源，例如协议、域名和端口。
- `siteTitle`：页面标题或可识别的学校名称。
- `displayName`：用户可编辑的任务名称。
- `status`：`running | paused | complete | stopped | archived`。
- `pauseReason`：材料、必填项、导航、API、页面访问或其他错误。
- `createdAt`、`updatedAt`、`lastOpenedAt`。
- `pageOrder`：已处理页面 ID 的顺序。
- `pages`：页面快照映射。
- `materials`：任务中发现、选择或从网站下载的材料记录。
- `audit`：最后一次审核输入指纹、状态、报告和时间。

### 标签页绑定

`tabId -> taskId` 绑定保存在 `chrome.storage.session`。标签页关闭时删除绑定和网页标色缓存，但保留 `ApplicationTask`。后台运行锁继续按 `tabId` 隔离，持久结果写回 `taskId`。

### PageSnapshot

页面快照只保存审核所需数据：

- 页面稳定 ID、显示名称、规范化 URL 和采集时间。
- 字段语义指纹、标签、类型、是否必填。
- 网页当前值、资料期望值、匹配来源和置信度。
- 回读状态：一致、需确认、冲突、未匹配、受保护。
- 页面材料控件及对应候选、实际写入结果和网站回显。

不得保存密码、验证码、Cookie、Authorization、API Key、CSRF 值、隐藏会话字段及其他安全令牌。普通隐藏业务字段默认也不进入审核，除非其具有明确可见标签且属于申请数据。

## 材料采集与抽样

### 来源优先级

1. 网站当前提供、且用户可见可点击的同源下载或预览入口。
2. 本次自动上传时记录的本地材料副本。
3. 仅有网站回显文件名时，保存元数据并标记“无法取得文件内容”。

最终审核只读取公开页面中的下载或预览入口，不猜测隐藏接口，不提交表单，不利用会话令牌拼接未展示地址。

### PDF 抽样

- 1 至 3 页：全部检查。
- 4 页及以上：首页、中间页和末页。
- 身份证等短身份证明：全部页面。
- 相同文件和相同页码使用稳定抽样，保证重复审核结果可复现。

用户原先提出的随机抽页以稳定抽样替代，原因是稳定抽样便于复查和缓存，也不会出现相同材料每次检查不同页面的问题。

### 能力降级

1. 使用 `pdfjs-dist` 在扩展本地读取 PDF 页数、提取文本并将选定页面渲染为抽样图像；不把这项能力扩展成 Word/PDF 个人资料导入。
2. Responses API 和中转支持 `input_image` 时，发送抽样页图像进行内容核验；支持 `input_file` 且文件满足大小限制时，可发送由抽样页组成的临时 PDF。
3. 不支持多模态但 PDF 可提取文本时，发送抽样页文本、文件名、类别和页码。
4. 扫描版 PDF 无文本且接口不支持图像时，只检查元数据，并在报告中明确标记“未完成视觉核验”。
5. 不允许把能力降级伪装为材料内容已经检查。

## AI 审核协议

审核输入使用结构化数据，包含选中任务、用户本地资料、页面快照、材料元数据及可用的抽样内容。API Key、Cookie 和安全字段永不进入提示词。

模型返回结构化 JSON：

- `summary`：总体结论和计数。
- `issues`：问题列表。
- `issues[].severity`：`critical | warning | info`。
- `issues[].taskId`、`pageId`、`fieldFingerprint`、`materialId`。
- `issues[].title`、`evidence`、`expected`、`actual`、`recommendation`。
- `unchecked`：未完成检查的页面或材料及原因。
- `confirmed`：模型明确核对一致的项目摘要。

报告解析失败时保留原始文本用于诊断，但 UI 不把未解析内容显示为成功报告。

### 缓存

审核指纹由以下内容稳定生成：

- 选中任务及页面快照。
- 本地资料的审核相关字段。
- 材料 ID、大小、修改时间、来源和抽样页。
- API 模式、模型名称和审核协议版本。

指纹未变化时复用报告。用户可以手动选择“重新审核”，但 UI 必须说明会再次调用 API。

## UI 设计

### 弹窗

弹窗保持当前的工作型密度，不增加营销文案或大面积装饰。

- 当前网站标题与任务状态。
- 当前步骤、已处理页面数、已填字段数。
- 一致、冲突、缺项、材料待确认计数。
- 当前网站逐页历史。
- 当前网站最后审核摘要。
- 底部批次汇总与“打开统一审核”按钮。

未绑定任务时仍显示当前页面识别状态和现有单页填充入口。

### 审核中心

审核中心使用独立的 WXT 页面 `entrypoints/audit/`。弹窗通过 `chrome.tabs.create` 打开该页面，工作台继续只负责资料、材料和 API 配置，避免两种长流程互相干扰。

- 左侧或顶部为任务筛选与批次选择。
- 主列表按学校展示状态、页面、冲突、材料和最后审核时间。
- 当前网站任务置顶并高亮。
- 发送前使用清单确认层，列出实际外发范围。
- 报告按学校折叠，严重问题默认展开。
- 每条问题提供“打开对应网站”或“定位当前标签页”的动作；没有打开标签页时只显示页面名称和记录，不自动重新导航。

## 错误处理

- 单个网站不可访问：该任务标记未检查，其他任务继续。
- 下载入口失效：回退本地材料或元数据，并记录来源。
- API 超时或 `502`：保留采集结果，显示可重试状态。
- 多模态不支持：执行明确的文本或元数据降级。
- 模型返回无效 JSON：不覆盖已有成功报告，显示解析失败。
- 页面在采集期间变化：丢弃旧页面结果并重新读取，禁止把旧页面结果写入新页面。
- 浏览器或扩展重启：从 `chrome.storage.local` 恢复任务和报告；运行中的任务恢复为暂停，必须由用户继续。

## 隐私与安全

1. 统一审核必须手动触发并二次确认。
2. 确认层显示发送的学校、页面、材料和抽样页，不只显示笼统提示。
3. 任务、页面快照和报告默认保存在本地浏览器。
4. 不采集密码、验证码、Cookie、API Key、CSRF 和隐藏会话令牌。
5. 不自动执行修改、上传、下一步或提交。
6. 网站下载只使用页面明确展示的同源入口。

## 测试与验收

### 自动化测试

- 任务创建、更新、归档和恢复。
- 标签页绑定与任务持久化分离。
- 关闭标签页不删除任务。
- 多标签页状态、标色和历史互不覆盖。
- AI 请求最多并发 2 个。
- 页面快照过滤安全字段。
- 审核指纹稳定且数据变化后失效。
- 审核 JSON 解析、无效返回和旧报告保留。
- 材料来源选择、稳定抽样和能力降级。
- 当前网站任务排序与批次默认勾选。

### 浏览器验收

1. 使用两个不同来源的本地模拟报名站点，同时启动连续填写，验证任务独立、API 排队和弹窗当前网站优先。
2. 关闭其中一个标签页，验证任务仍出现在审核中心。
3. 修改一个页面值，验证审核指纹变化且旧报告失效。
4. 使用当前已登录的东南大学系统读取真实 13 步导航、已填写字段和材料页面。
5. 在东大系统验证当前网站展示、页面快照和统一审核预检。
6. 全程不点击“申请信息提交”或任何最终确认操作。

## 非目标

- 不开发 Word/PDF 资料文档自动导入。
- 不自动修复最终审核发现的问题。
- 不自动提交、确认、支付、处理验证码、选择志愿或导师。
- 不为东南大学建立专用核心匹配器或路由表。
- 不承诺所有中转都支持文件或图像输入；能力不足时必须明确降级。
