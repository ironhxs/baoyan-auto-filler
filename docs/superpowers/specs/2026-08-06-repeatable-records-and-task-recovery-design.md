# 保填：重复条目与多项目恢复设计

日期：2026-08-06

## 目标

在不针对某一所学校写专用选择器的前提下，改善以下体验：

1. 已存在的外语、家庭成员、论文、奖励、经历等重复行能够按实际内容核验，避免仅凭行号造成交叉匹配和误报。
2. 空表格或条目不足时，扩展能识别通用的“新增”入口，补足与个人资料相匹配的行后再填写。
3. 同一网站的多个预推免项目可同时连续填写；每个项目独立继续、暂停和审计。
4. 返回已处理页面时，恢复上一次扫描结果、建议、勾选状态和网页标色；页面语义未变化时不重复调用 AI。

不会自动提交、点击最终确认、处理验证码、承诺书、导师/志愿选择或支付。

## 现状与根因

- 重复字段的本地匹配使用 `groupLabel + rowIndex + columnLabel`。当页面中已有行的排序与资料保存顺序不一致时，同一条资料会被错误地分配给另一行。
- `prepareRepeatRows` 已能尝试新增行，但只返回新增数量。它不会为每个组保存新增计划或失败原因，也不能以“已有条目的主标识”判断哪些资料尚未占位。
- 网页标色以标签页 ID 存于 `chrome.storage.session`。扫描建议本身没有按“任务 + 页面语义”持久化；回到页面时只能尝试恢复标色，不能恢复侧栏扫描结果。
- 连续填写状态同样以标签页 ID 保存。服务工作进程暂停、后台标签页被节流或用户切换到其他项目后，没有可恢复的项目级待执行检查点。

## 方案比较

### 方案 A：只放宽新增按钮与行号匹配

修改范围最小，但不能可靠处理已有行顺序变化、多项目后台恢复和侧栏建议恢复，因此不采用。

### 方案 B：项目级持久化状态 + 语义重复条目规划（采用）

将扫描、标色、连续填写检查点存入独立申请任务，并由任务 ID 与语义页面键共同定位。重复条目通过“主标识优先、剩余资料补行”规划。适配范围广，且保留现有本地优先、AI 兜底策略。

### 方案 C：为不同系统建立页面适配器

精度可能更高，但维护成本高，且违背保持通用适配的目标；只作为未来对极端网页的可选扩展，不纳入本次。

## 设计

### 1. 重复条目规划

新增 `repeatable-records` 工具层，输入网页扫描字段、个人重复资料和页面上下文，输出每个资料组的计划：

- `existingBindings`：网页已有行与资料条目的绑定。
- `missingItems`：需要新增的资料条目。
- `unmatchedRows`：已有但不能可靠匹配的行，保留人工检查。
- `requiredRows`：目标行数与新增前后行数。

主标识按组定义：

- 外语水平：考试名称/等级（如 CET-4、CET-6、IELTS）。
- 家庭成员：姓名；名称缺失时关系作为低置信候选。
- 学术成果：论文/成果名称。
- 奖励情况：获奖/竞赛名称。
- 学习工作经历：学校或单位 + 起止时间组合。

主标识匹配成功后，列顺序完全由 `columnLabel` 语义决定，不依赖资料字段或网页列顺序。没有可靠主标识时，只有“空行按顺序补齐”允许位置回退；已有非空行不会被覆盖。

### 2. 通用新增流程

扫描前由规划器确定缺失条目。内容脚本对目标表格执行以下安全步骤：

1. 找到相应资料组及其可见“新增/添加/＋”控件。
2. 每新增一行，等待 DOM 中数据行或可填写控件确实增加。
3. 达到目标行数后重新扫描，确认新行的组名、行数和列名。
4. 只填写规划器分配给空字段的值；失败时保留既有内容并返回明确原因。

侧栏显示“将新增 N 条”的分组摘要与失败项；自动连续填写时依旧仅对非低置信、非高风险字段执行写入。

### 3. 页面分析缓存与恢复

在 `ApplicationTask` 中增加按语义页面键保存的分析记录。每条记录包括：

- 扫描得到的字段和匹配建议；
- 用户在侧栏的勾选状态；
- 网页标色；
- AI 是否调用、缓存命中信息与分析版本；
- 新增计划与执行结果。

语义页面键继续基于规范化 URL + DOM 签名。重新打开页面时，先比较当前键：

- 一致：恢复侧栏结果和标色，不调用 AI；重新读取当前值，仅把变化字段转为“需核对”。
- 不一致：创建新的页面分析记录并执行扫描。

标色的会话缓存只作为即时加速层；任务内页面分析是恢复的持久来源。

### 4. 多项目连续填写与恢复

连续填写状态从单纯的 `tabId` 会话状态扩展为任务检查点：状态、最近语义页面键、历史、暂停原因、材料确认状态、下次继续条件与更新时间。

- 同一标签页仍只绑定一个任务。
- 多个标签页分别持有不同任务；不会按学校域名合并。
- 页面加载、标签页重新激活和扩展后台恢复时，都查找该标签页绑定的任务检查点。仅在状态为 `running` 且页面已稳定时继续；`paused` 和 `complete` 只恢复显示，绝不擅自重跑。
- 延迟续跑用浏览器的持久调度机制触发，并在执行前重新确认任务、标签页和语义页面一致，避免对错误页面操作。

任务无法重新关联到一个仍打开的标签页时，保持暂停记录而非创建或覆盖其他同校项目。

### 5. 测试与验收

新增自动化回归测试覆盖：

1. CET-4/CET-6 已有行顺序反转时，日期与成绩仍匹配正确条目。
2. 空论文/奖励表格生成缺失条目新增计划；已有非空条目不会重复新增。
3. 同站点两个不同项目任务互不覆盖，分别保留检查点。
4. 页面语义键相同的回退页面命中缓存；DOM 签名变化后缓存失效。
5. 连续填写恢复只允许 `running` 任务继续，`paused` / `complete` 不自动触发填写。

验收还包括现有编译、全量脚本测试、构建，以及实际浏览器中不提交表单的检查。版本号将从 1.3.4 升级并推送 `main` 与版本标签。

## 范围外

- 针对特定学校的生产环境 DOM 特例。
- 自动处理验证码、文件以外的确认操作、最终提交。
