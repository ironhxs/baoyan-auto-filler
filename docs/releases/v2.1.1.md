# 保填 2.1.1

2.1.1 把 Agent 从“看到当前页再决定”推进到“先理解整个报名任务，再逐页执行”，同时补齐多项目隔离、任务命名和动态新增记录的安全闭环。

## 主要更新

### 跨页先收集、后规划

- 连续填写先收集所有可安全访问页面的完整题干、注释、日期示例、禁用字符、表头、当前值和控件结构；
- 所有页面组成同一份跨页蓝图后，只调用一次全局规划链路，再通过安全的“上一步”返回起点逐页执行；
- 如果网站因空白必填项阻止只读翻页，会降级为边填写边规划，并明确记录原因；
- 跨页状态、蓝图和方案写入任务断点，扩展后台被浏览器回收后仍可恢复；
- 永远不点击最终提交、确认报名、承诺书、导师/志愿、验证码、支付或删除操作。

### 页面上下文真正进入 Agent

“识别并预览”和自动填写现在都把以下内容送入页面规划请求：

- 完整题目文本和页面可见说明；
- 字段注释、占位提示和表格列顺序；
- 日期格式示例、禁用字符和长度上限；
- 上传项题目与网页已有材料状态；
- 当前页面的学校、院系和项目身份证据。

这修复了“扫描结果看到了说明，但模型实际没有收到完整说明”的问题。

### 学校、院系、项目名称不再串台

- 任务主名称优先使用“学校 · 院系”；
- 页面没有可靠院系时，为同一学校稳定显示“项目 1、项目 2、项目 3”；
- 支持在当前网站和统一审核中自定义任务名称，也可一键恢复自动名称；
- 本科院校、本科院系和本科专业作为申请人来源身份被严格排除，不再误判成目标院系；
- 证据不足时，身份 Agent 只能引用页面真实文本，不能把个人资料中的本科院系当答案；
- 同一网站 URL 中明确的项目标识发生变化时，会建立新的独立任务，避免在同一标签页切换项目后覆盖前一个项目的进度。

### 动态新增记录

家庭成员、项目经历、论文和获奖情况等动态“新增记录”继续采用单弹窗顺序执行：

1. 打开一个记录编辑器；
2. 从真实弹窗读取字段顺序、必填状态、题目和注释；
3. 先按本地资料确定性投影；
4. 缺少可可靠转换的字段时，只把当前单条资料和当前弹窗 schema 交给 Agent；
5. 校验字段白名单、来源记录、证据字段、格式和禁止字符；
6. 写入后回读，确认新增行真实出现才继续下一条；
7. 无法安全完成时取消当前记录并保留人工审核，不保存半条记录。

Agent 输出不能引用其他记录、未知字段、任意选择器、脚本或网页按钮。

### 界面与标色

- 移除“保守 / 标准 / 尽量填充”三档，统一为一套可回读、可审核的安全策略；
- 网页控件只使用 `outline` 标色，不改变输入框尺寸；
- 对包含多行嵌套表格的题目单元格进行可恢复的顶部对齐，避免新增行后左侧题目被挤到表格底部；
- 当前任务和统一审核都显示更容易区分的学校、院系或项目编号。

## API 与 Fast 模式

- 继续支持 Responses 和 Chat Completions；
- 继续支持可选 Fast 模式，并把该设置纳入计划缓存指纹；
- 动态记录补全、单页计划和跨页计划都走用户自行配置的中转 API；
- 401、403、429、502 和网络错误不会触发偷偷换协议、换模型或无限重试。

## 安全边界

- 资料和任务记录默认保存在浏览器本地；
- 只有用户启用 AI 增强后，当前请求所需的页面语义和候选资料才会发给用户配置的模型服务；
- 密码、验证码、授权头、令牌、Cookie、支付信息和敏感 URL 参数会在快照阶段过滤；
- 自动化仍不会提交报名、选择导师/志愿、勾选承诺书、处理验证码、支付或删除数据。

## 升级

解压缩加载用户请构建或下载 2.1.1 后，在浏览器扩展管理页选择新的构建目录，或用新构建文件覆盖原加载目录后点击“重新加载”。确认扩展详情显示名称“保填”、版本 `2.1.1`。浏览器本地资料、任务记录和 API 配置不会因普通代码覆盖而清空；更换浏览器配置目录前仍建议导出资料备份。

## 验证范围

本版本在发布前执行离线回归、TypeScript 编译、Chrome MV3 构建和 Firefox MV2 构建。真实学校页面是否允许完整只读翻页由各系统的必填校验决定；无法只读遍历时会使用上述安全降级，不把未实测站点宣称为已完成真实全流程验收。
