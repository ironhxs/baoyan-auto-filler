# 保填

[English](README.en.md) | 中文

一款面向推免报名场景的 Chrome / Edge 表单辅助填充扩展。保留 1.0 版整页 AI 语义匹配链路，并增加本地精确值校验、已填信息核对、多步骤连续填写、重复表格、手动速填和 PDF 证明材料合成。资料默认保存在浏览器本地，无需注册账号。

## 功能

### 智能表单填充
- 集中管理七类资料：基本信息、家庭成员、学习信息、外语水平、学习和工作经历、学术成果、奖励情况
- 默认的“AI 增强复核”会像 1.0 版一样将当前安全字段交给 API 做整页语义匹配；本地精确值用于防止模型改写事实
- 可关闭 AI 增强复核，改为仅在本地规则无法匹配时调用 API；未配置 API 也能完成基础填充
- 支持家庭成员、外语成绩、经历、成果和奖励等重复表格；既能按资料条数安全新增表格行，也能处理“新增后打开弹窗或抽屉”的记录编辑界面
- 重复表格按“分组 + 行号 + 子字段语义”匹配，网页列顺序与本地资料顺序不同时仍能正确对应；规则不确定时可由 AI 兜底，但返回值必须来自同一条已保存资料
- 弹窗或抽屉新增记录时，按子字段语义而不是页面排列顺序填写；会逐条回读，并且仅点击该记录窗口内的“保存 / 确定 / 添加”类按钮
- 同类重复资料只有一个大文本框时，会把该条记录的多个子字段汇总为可读文本；字段不明确、必填项无法回读或窗口出现高风险操作时会暂停，不会猜填
- 兼容“本科学校 / 本科专业 + 选择”类弹窗控件，只点击与保存值完全一致的选项
- 支持 React 等框架页面的表单（使用原生 setter 触发变更）
- 绿色表示已回读验证，橙色表示建议检查，红色表示回读不一致
- 扫描预览后会把同样的绿 / 橙 / 红状态直接标在网页控件上；点击侧边栏结果可滚动并聚焦对应字段
- 页面切换后再次返回时，会按字段语义指纹恢复绿 / 橙 / 红标记，不依赖字段顺序或某个学校的固定路由
- 提供七类资料的手动速填，用于处理自动匹配未覆盖的复杂控件

### 后台连续填写
- 可在关闭弹窗或切换页面后继续运行，不要求用户一直等待在侧边栏
- 多个学校标签页可各自运行连续填写；页面扫描可并行，所有 AI 请求统一排队且最多同时执行 2 个
- 每个学校的页面快照、逐页记录、材料状态和最终检查报告保存为本地任务；关闭标签页只会暂停任务，不会删除记录
- 当前页填写并回读后，只点击明确的“下一步 / 保存并下一步”等安全按钮
- 普通 URL 跳转和单页应用内部切换均会在新页面重新扫描，禁止把旧页的下一步命令重放到新页
- 遇到未处理的必填项会暂停并提示；最多连续处理 20 页
- 侧边栏保留本次全部逐页记录，显示每页识别、一致、冲突、填入和 AI 复核数量
- 到最终审核页自动停止，绝不会点击最终提交、确认提交、支付、验证码、承诺书、志愿或导师选择

### 当前网站与统一最终检查
- 弹窗优先显示当前网站的步骤、核对一致、冲突、缺项、材料待核和上次检查结果，不用在多所学校之间来回寻找状态
- 独立的统一审核中心汇总本批次已完成或暂停的学校任务；当前网站置顶，可按学校选择检查范围
- 最终检查必须手动生成预检清单，并在看到学校、页面、字段、材料和抽样页数量后再次勾选确认，未确认的后台消息会被拒绝
- 最终检查是只读操作：不会修改字段、重新上传材料、点击下一步或执行任何提交
- 短 PDF 和身份材料检查全部页面；较长 PDF 固定抽取首页、中间页和末页。同一材料重复检查使用稳定抽样，便于复核与缓存
- Responses 线路支持图像时会核对抽样页图像；中转不支持图像时明确降级为文本或元数据检查，并在“未完成检查”中列出，不能伪装为已核验

### 本地备份与恢复
- 支持导出七类资料及重复条目，并提供两种 JSON 导入方式：更新同名资料，或只新增缺少字段和非重复条目
- API Key 和证明材料不包含在资料备份中

### 证明材料管理
- 支持上传图片（JPG/PNG/WebP）和 PDF 文件
- 按分类管理材料（身份证明、学历证明、资格证书、个人照片等）
- 支持图片与 PDF 的扩展内真实预览、重命名、移动分类、删除
- 兼容原生文件框以及由按钮触发的透明 / 隐藏文件框；按页面声明的格式和大小限制筛选材料
- 扫描到明确的文件上传项时，可根据网页语境与材料文件名、说明和分类推荐证件照、身份证、成绩单、排名证明、四六级、获奖及学术成果等文件；可切换多个候选，文件默认不勾选，必须预览并确认后才会批量附加到网页
- 连续填写遇到明确且非低置信的材料匹配时，会先把候选写入文件框并立即暂停；必须在弹窗中预览实际文件和题目名称，确认后才继续下一页

### PDF 合成
- 从证明材料中选取图片和 PDF，拖拽排序后合并为一个 PDF
- 支持本地上传新文件（自动存入证明材料）
- 图片自动缩放适配 A4 页面，居中留白
- 合成结果保存到证明材料，随时下载
- 纯浏览器端操作，无需服务端

### API 配置
- 同时支持 OpenAI 兼容的 Chat Completions（`/chat/completions`）与 Responses（`/responses`）协议
- 可连接国内厂商、聚合平台、第三方中转及本地模型服务
- 预置主流供应商配置，也支持自定义 Base URL 和模型名称
- 支持 Fast 模式（`service_tier: fast`）与不含个人资料的“测试 API 连接”按钮
- 每次扫描都显示“AI 已真实调用 / 未配置 / 调用失败”及返回项数
- 可选 Fast 模式；开启时请求携带 `service_tier: "fast"`，默认关闭

## 安装

### 从 Release 安装（推荐）

前往 [Releases](../../releases) 下载对应压缩包：

| 文件 | 适用浏览器 |
|------|-----------|
| `baotian-chrome.zip` | Chrome / Edge / Brave 等 Chromium 内核浏览器 |
| `baotian-firefox.zip` | Firefox |

**Chrome / Edge：**

1. 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）
2. 开启右上角「开发者模式」
3. 解压下载的 zip，点击「加载已解压的扩展程序」，选择解压后的目录

**Firefox：**

1. 打开 `about:debugging#/runtime/this-firefox`
2. 点击「加载临时附加组件」
3. 选择下载的 zip 文件（Firefox 会将扩展标记为临时，重启后需重新加载）

### 从源码构建

```bash
npm install
npm run build            # Chrome
npm run build:firefox    # Firefox
```

构建产物在 `.output/` 目录，可在浏览器扩展管理页面以「加载已解压的扩展程序」方式加载。

### 开发更新且保留资料

不要删除旧扩展，也不要每次解压到一个新目录。推荐直接把本仓库的 `.output/chrome-mv3` 作为固定扩展目录：

1. 第一次在 `edge://extensions/` 中选择「加载解压缩的扩展」，指向 `.output/chrome-mv3`
2. 修改代码后运行 `npm run build`
3. 在扩展管理页点击保填的「重新加载」，或在保填设置页点击「重新加载扩展」
4. 刷新正在测试的报名网页

只要扩展目录和扩展 ID 不变，IndexedDB 与 `chrome.storage` 中的七类资料、材料文件和 API 配置会保留，不需要重新导入 JSON 或文档。不要点击「移除扩展」，也不要清除该扩展的网站数据。

需要开发热更新时运行 `npm run dev`。WXT 会启动专用开发浏览器并自动更新大部分界面代码；内容脚本或后台脚本变化后仍建议刷新目标网页。开发浏览器使用独立浏览器配置，第一次导入后，后续代码更新会继续沿用该配置中的资料。

### 打包

```bash
npm run zip            # Chrome
npm run zip:firefox    # Firefox
```

产物在 `.output/` 目录，可直接上传到 Chrome Web Store 或 GitHub Releases。

## 使用方式

1. **录入资料**：在工作台维护七类推免资料；外语、家庭成员、经历、成果和奖励可添加多条
2. **备份资料**：首次录入后导出一份本地备份，换设备或重装前再次备份
3. **填充当前页**：浏览报名页 → 点击扩展图标 → 识别并预览 → 确认后填充
4. **连续填写**：选择「后台连续填写到最终审核」；遇到材料或其他必填阻塞时，预览确认后继续
5. **统一检查**：从弹窗打开「统一审核中心」，选择本批次任务，查看预检范围并二次确认后手动运行最终检查
6. **人工审核**：按报告和网站最终页逐项检查日期、排名、选择项、重复行与材料，再由本人决定是否提交
7. **可选 AI**：需要低置信字段匹配或最终检查时，在设置中填写 API 地址、协议、Key 和模型；Codex 类模型或仅支持 Responses 的中转请选择 `Responses`

> 当前版本不提供 Word / PDF 个人资料的 AI 自动导入。证明材料管理和 PDF 合成功能不受影响。

## 安全与隐私

- 七类资料、证明材料和 API 配置保存在当前浏览器中，扩展没有自建业务服务器
- 只有主动使用 AI 匹配，或在统一审核中心完成预检并二次确认最终检查时，本次请求所需的字段文本、材料名称和可用抽样页内容才会发送到用户自行配置的模型服务商
- 最终检查不会发送密码、验证码、Cookie、API Key、CSRF、Authorization、隐藏会话字段或下载鉴权头；网站材料只通过页面中用户可见、可点击的同源入口在本地只读获取
- 扩展不会自动提交表单，不会处理验证码、支付、承诺书、志愿或导师选择；连续填写只会为明确材料匹配写入文件框并暂停等待预览确认
- 不同学校页面结构和校验规则不同，所有结果都应由本人最终核对

## 技术栈

- **框架**: [WXT](https://wxt.dev/) (基于 Vite 的浏览器扩展框架)
- **语言**: TypeScript
- **UI**: 原生 HTML/CSS，无框架
- **PDF**: [pdf-lib](https://pdf-lib.js.org/)
- **PDF 检查**: [PDF.js](https://mozilla.github.io/pdf.js/)
- **拼音**: [pinyin-pro](https://github.com/nicoleee-h/pinyin-pro)
- **数据存储**: IndexedDB + chrome.storage.local

## 项目结构

```
├── entrypoints/
│   ├── background.ts        # Service Worker：消息路由、LLM 调用
│   ├── content.ts           # 内容脚本：扫描 DOM、填充表单
│   ├── popup/               # 弹出窗口：扫描→确认→填充
│   ├── audit/               # 统一审核中心：任务选择、预检、最终检查报告
│   └── options/             # 选项页：信息管理、材料管理、PDF 合成、设置
├── utils/
│   ├── db.ts                # IndexedDB 封装
│   ├── storage.ts           # chrome.storage 封装
│   ├── matcher.ts           # LLM 语义匹配
│   ├── local-matcher.ts     # 本地确定性字段匹配
│   ├── profile-schema.ts    # 七类资料结构与外语条目推导
│   ├── pdf-merge.ts         # PDF 合成逻辑
│   └── providers.ts         # API 供应商预设
└── public/icons/            # 静态图标资源
```
